# CrystalAid: бот, тикеты в личных сообщениях и ПТ

Дата: 2026-11-01. Заменяет разделы 4.1 и 4.3 основной спецификации там, где они расходятся.

## Решения владельца

- Сервер на 300 000 участников.
- Пользователь пишет `/help` в определённом канале, появляется модальное окно с вопросом «Что хотите спросить?», ответ ограничен 300 символами.
- Дальше тикет идёт только через личные сообщения с ботом. Каналов и веток для тикетов нет.
- Тикет приходит саппортам, у которых сейчас ПТ. ПТ длятся час: 00:00–01:00 и так далее.
- Перед получением тикета саппорт проходит антибот-проверку: выбирает картинку с нужным предметом. Кто первым ответил верно, тот разбирает тикет.
- Принятый или закрытый тикет взять нельзя.
- Всё логируется в канал на другом сервере, транскрипты сохраняются.
- Все уведомления идут в личные сообщения, например за 5 минут до ПТ.
- Админы ветки и разработчики задаются по ID пользователя в конфиге и получают меню настроек.

## Принятые разработчиком допущения

- Один открытый тикет на человека, новый тикет не чаще раза в 5 минут.
- Дальнейшая переписка идёт через личные сообщения с ботом в обе стороны. Пользователь видит «Поддержка», настоящее имя саппорта видно только в логах.
- ПТ назначают админы и кураторы с правом `shifts.edit` через меню бота: час и саппорт. Часовой пояс из конфига.
- Если на ПТ никого нет, тикет ждёт, пользователю сообщается об этом, а бот предложит тикет при начале следующего ПТ.
- Неверный ответ на проверку лишает права взять именно этот тикет. Непринятый за 5 минут тикет предлагается снова, и событие попадает в лог.
- Закрывает тикет саппорт кнопкой. После закрытия пользователь получает оценку 1–5, а в лог уходит файл транскрипта.
- Если личные сообщения закрыты, запись об этом попадает в лог.
- `developers` получают меню разработчика с диагностикой и все права админа.

## Конфиг

```json
{
  "guildId": "",
  "timezone": "Europe/Moscow",
  "roles": { "support": [""], "curator": [""], "admin": [""] },
  "users": { "admins": [""], "developers": [""] },
  "channels": { "help": "", "log": "" }
}
```

`channels.help` — канал, где работает `/help`, в других местах бот вежливо отвечает, куда идти. `channels.log` может находиться на другом сервере: бот должен быть там и иметь право писать. Прежние поля `ticketCategory`, `ticketPanel`, `reports`, `audit` становятся необязательными.

## Архитектура

- `apps/bot` на discord.js, без доступа к базе. Вся логика в API, бот вызывает `/internal/*` с сервисным токеном.
- Интенты: `Guilds`, `GuildMembers`, `DirectMessages`. `GuildPresences`, `GuildMessages`, `GuildVoiceStates` и `MessageContent` не включаются: они дают лавину событий на таком сервере, а текст в личных сообщениях доступен и без `MessageContent`. Онлайн и голос переходят в подпроект 4.
- Кэш участников ограничен составом ветки. При запуске бот запрашивает участников сервера, отфильтровывает держателей ролей и отправляет один `member.snapshot`.
- Захват тикета — один атомарный `UPDATE ... WHERE status = 'open'`.
- Планировщик в боте раз в 30 секунд забирает из API напоминания и непринятые тикеты. Выдача напоминания идемпотентна.

## API `/internal`

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/internal/tickets` | Создать тикет, вернуть саппортов на ПТ с заданиями проверки |
| POST | `/internal/tickets/:id/claim` | Ответ на проверку и атомарный захват |
| POST | `/internal/tickets/:id/messages` | Сохранить сообщение |
| POST | `/internal/tickets/:id/close` | Закрыть, вернуть транскрипт |
| POST | `/internal/tickets/:id/rating` | Оценка 1–5 |
| GET | `/internal/tickets/active` | Активный тикет по участнику переписки |
| GET | `/internal/tickets/due` | Тикеты для повторного предложения |
| GET, PUT, DELETE | `/internal/pt` | Расписание ПТ |
| GET | `/internal/pt/reminders` | Выдать напоминания один раз |
| GET, PATCH | `/internal/menu/settings` | Настройки для меню |
| GET | `/internal/diagnostics` | Диагностика для разработчика |

Все маршруты проверяют уровень действующего лица на сервере, а не на боте.

## Данные

Новые таблицы: `pt_slots` (`guild_id`, `starts_at`, `user_id`, `reminded_at`, unique по первым трём), `ticket_challenges` (`ticket_id`, `user_id`, `answer`, `attempted_at`, unique по первым двум, `answer` никогда не уходит клиенту). В `tickets` добавляются `claimed_by`, `claimed_at`, `offered_at`, `first_response_at`, `closed_at`, `rating`.

## Меню

- `/menu`: для админа — ставки, нормы, расписание ПТ на дату, логи ошибок доставки; для куратора — расписание.
- `/dev`: для разработчиков — версия, размер очереди, число открытых тикетов, состояние базы и Redis, последние ошибки.
- `/help` — создание тикета, для всех, только в `channels.help`.

## Требование Discord

Для бота с доступом к 10 000 и более пользователей интент Server Members выдаётся только после заявки в Developer Portal. Без него бот не увидит изменения ролей. Подать её должен владелец приложения.
