# CrystalAid: дизайн-система и каркас Activity

Дата: 2026-11-01. Статус: на проверке. Подпроект 2 спецификации `2026-11-01-crystalaid-staff-design.md`, использует ядро из подпроекта 1.

## 1. Цель

Рабочий каркас Activity и библиотека компонентов, на которых строятся все экраны следующих подпроектов.

**Успех:**
- Сотрудник открывает Activity, входит автоматически и видит разделы своего уровня.
- Панель не ломается на контрольных размерах экрана: нет горизонтальной прокрутки, наложений и обрезанного важного текста.
- Все компоненты управляются с клавиатуры и проходят автоматическую проверку доступности.
- Новый экран собирается из готовых компонентов и токенов без своего CSS для цветов и отступов.

**Не входит:** данные и логика тикетов, смен, статистики, магазина, состава и отчётов; покупка тем; realtime; настоящий запуск в Discord.

## 2. Структура

```text
packages/design-system   токены, темы, компоненты, тесты компонентов
packages/i18n            словари ru и en, функция перевода
apps/activity            вход, клиент API, каркас, разделы, витрина /kit
```

Новые зависимости: `react`, `react-dom`, `vite`, `@vitejs/plugin-react`, `@discord/embedded-app-sdk`, примитивы Radix только для используемых компонентов, `lucide-react`, `@fontsource-variable/inter`, `@testing-library/react`, `@testing-library/user-event`, `jsdom`, `axe-core`, `@playwright/test`.

Шрифт и иконки поставляются вместе с приложением: Discord блокирует внешние адреса внутри Activity.

## 3. Дизайн-система

### 3.1 Токены

Все значения задаются CSS-переменными в `packages/design-system/src/tokens.css`.

- Цвет: `--color-background`, `--color-surface`, `--color-surface-elevated`, `--color-surface-hover`, `--color-border`, `--color-foreground`, `--color-muted`, `--color-primary`, `--color-on-primary`, `--color-success`, `--color-warning`, `--color-danger`.
- Отступы: `--space-1` … `--space-11` соответствуют 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80.
- Радиусы: `--radius-1` … `--radius-7` соответствуют 4, 6, 8, 10, 12, 16, 20.
- Типографика: Display, Heading, Subheading, Body, Label, Caption, Mono. Крупные размеры через `clamp()`, числа табличные.
- Движение: `--motion-fast` 120 мс, `--motion-base` 180 мс, `--motion-slow` 240 мс. При `prefers-reduced-motion: reduce` анимации отключаются.

CSS Modules компонентов используют только токены. Проверка в lint запрещает шестнадцатеричные цвета вне файлов токенов и тем.

### 3.2 Темы

Значения шести тем — из раздела 9 основной спецификации. Статусы: success `#5BD6A0`, warning `#F5C451`, danger `#F47174`, общие для всех тем.

Тема применяется атрибутом `data-theme` на корне. Выбор хранится в `localStorage` с защитой от недоступного хранилища. Пока работает только бесплатная тема Кристалл, остальные доступны на витрине `/kit` и подключатся к магазину в подпроекте 5. Неизвестное значение заменяется на Кристалл.

Контраст всех тем с цветами статусов проверяется автоматическим тестом на пороге AA 4,5:1.

### 3.3 Компоненты

| Группа | Компоненты |
|---|---|
| Действия | Button, IconButton |
| Отображение | Avatar, Badge, Card, StatCard, ProgressBar, Table |
| Навигация | Tabs, Tooltip, Dropdown |
| Окна | Modal, Drawer, Toast |
| Формы | Input, Select, Checkbox, Toggle |
| Состояния | Skeleton, EmptyState, ErrorState |

Modal, Drawer, Dropdown, Select, Tabs, Tooltip, Checkbox, Toggle и Toast используют Radix Primitives. Остальные — свои.

Интерактивные компоненты поддерживают default, hover, active, focus-visible, disabled, loading, selected, error и success там, где состояние имеет смысл. Hover никогда не единственный способ получить функцию. Минимальная область касания — 40 пикселей.

Table принимает колонки с приоритетом. На узком контейнере строки становятся карточками, а низкоприоритетные колонки уходят в раскрытие.

## 4. Каркас Activity

### 4.1 Вход

1. Запуск: `DiscordSDK`, `ready`, `authorize` с областями `identify` и `guilds`, `prompt: "none"`.
2. `POST /auth/activity` с `code` и `instanceId`.
3. `authenticate` с `discordAccessToken`, сессия хранится только в памяти.
4. `GET /me` определяет уровень и права.

Запросы идут на относительный путь `/api`. Он настраивается через URL Mapping в Discord, в разработке его проксирует Vite.

При `401 TOKEN_EXPIRED` клиент один раз незаметно повторяет вход и запрос. Одновременные запросы используют один повторный вход. Если он не удался, показывается экран ошибки с кнопкой «Повторить».

### 4.2 Экраны входа

| Условие | Экран |
|---|---|
| Идёт вход | Логотип и индикатор |
| `NOT_STAFF` | «Нет доступа» с текстом с сервера, включая случай без роли саппорта |
| `GUILD_REQUIRED` | «Откройте панель на сервере» |
| `INVALID_INSTANCE` | «Запустите панель заново» |
| `DISCORD_UNAVAILABLE`, сеть | «Не удалось подключиться» с кнопкой «Повторить» |

### 4.3 Навигация

Разделы описаны одной таблицей: `id`, ключ перевода, иконка, минимальный уровень, необязательное право. Видимость вычисляет чистая функция `visibleSections(level, permissions)`. Это только удобство: доступ проверяет backend.

| Уровень | Разделы |
|---|---|
| Саппорт | Обзор, Смена, Тикеты, Статистика, Магазин, Настройки |
| Куратор | + Состав, Смены состава, Все тикеты, Отчёты |
| Админ | + Роли и доступы, Зарплата, Нормы, Управление магазином, Журнал |

Текущий раздел хранится в состоянии приложения, отдельный роутер не используется. Каждый раздел загружается лениво и обёрнут в свою границу ошибок: сбой раздела показывает ErrorState и не роняет панель.

В этом подпроекте работают Обзор с данными `/me` и Настройки с выбором языка. Остальные разделы показывают EmptyState «Раздел появится в следующих версиях».

### 4.4 Раскладка

Раскладка выбирается по ширине контейнера через container queries.

| Режим | Условие | Вид |
|---|---|---|
| Компактный | Окно поверх чата (`ACTIVITY_LAYOUT_MODE_UPDATE`) или менее 320 px | Заголовок и одно главное действие |
| Узкий | менее 720 px | Нижняя панель: первые 4 раздела и «Ещё», остальное в Drawer |
| Средний | 720–1279 px | Боковая панель иконками с подсказками |
| Широкий | 1280–1919 px | Боковая панель с подписями |
| Очень широкий | от 1920 px | То же, контент ограничен шириной 1440 px по центру |

Высота задаётся через `dvh`, учитываются `safe-area-inset`. Значения проверяются на контрольных размерах и могут сдвигаться по контенту.

### 4.5 Разработка вне Discord

При `import.meta.env.DEV` и `VITE_DEV_MOCK=1` Activity работает с подставным SDK и ответами API, уровень меняется на витрине. Этот код подключается через динамический импорт внутри проверки `DEV`, поэтому не попадает в продакшен-сборку. Тест проверяет это по содержимому сборки.

Витрина `/kit` показывает все компоненты, состояния и темы и также доступна только в разработке.

## 5. Тексты

`packages/i18n` экспортирует словари `ru` и `en` и функцию `t(key, params)`. Набор ключей у словарей обязан совпадать, это проверяет типизация. Русский основной. Язык определяется по локали Discord, изменяется в Настройках и хранится локально. Форматирование чисел и дат через `Intl`.

## 6. Проверка

- **Unit:** токены, контраст, `visibleSections`, клиент API, повторный вход, i18n.
- **Компоненты:** Testing Library и axe, клавиатура для Modal, Drawer, Dropdown, Select, Tabs.
- **Браузер:** Playwright в режиме `VITE_DEV_MOCK` на размерах 320×568, 360×800, 375×667, 390×844, 412×915, 768×1024, 820×1180, 1024×768, 1280×720, 1366×768, 1440×900, 1536×864, 1920×1080, 2560×1440, 3440×1440.
- **На каждом размере:** нет горизонтальной прокрутки, навигация доступна, нет ошибок консоли; длинное имя в 40 символов не ломает панель; текст при масштабе 200% остаётся доступным; главные экраны проходят axe.
- **Сборка:** ни один файл не обращается к внешним доменам, `/kit` и подставной режим отсутствуют.
- **Вручную:** запуск в настоящем Discord после создания приложения.

## 7. Готовность

- `pnpm test`, typecheck, lint и браузерные проверки проходят.
- `pnpm --dir apps/activity run build` собирает статику.
- Компоненты витрины просмотрены по скриншотам на узком, широком и очень широком экране.
